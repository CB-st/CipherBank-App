Runtime conventions

RuleValue
BadgeINVOKE — C# method / RelayCommand (not HTTP)
ProjectsCipherBank-app · CipherBank-app.Core · CipherBank-app.ChallengePass
Session proofLab (default) · ChallengePassA1 · ChallengePassA2
Product APIIProductApi → mock or HttpProductApi (/v1)
Public quotesIPublicQuoteService → PublicApiClient (api.cipherbank.money)
Convert lockIndicative via POST /iquote; settle via product ConvertAsync
SQLite AndroidShip SQLitePCLRaw.lib.e_sqlite3.android only — exclude desktop natives from APK
Idle lockAppIdleLockService → AppSession.Lock + IPqChannel.Clear → Unlock

Unlock / seal call graph

Splash (≥900ms) + Boot
  → Welcome → Keys → BackupQuiz → SetPin.Seal
       → FinishCustodySetup → Seal → SeedWallets → CompleteUnlock(no bootstrap)
  → Unlock.PIN|Biometrics
       → Unlock* → CompleteUnlock(bootstrap)
            → CreateSession (Lab|A1|A2 proof)
            → Stream.Connect (disconnect-first) + Hub.Start
            → PrefsSync.PullMerge [+ AccountBootstrap]
  → Home

Idle / Profile.Lock → AppSession.Lock → PQ Clear → Unlock

Never on the wire

Mnemonic, BIP39 entropy, PIN plaintext, device secret, account private key, spend keys, PAN/CVV, full ACH account numbers. Public/product APIs receive public keys, sealed ciphertexts, handles, and masked last4 only.

Cold-start: show Splash (≥900ms), initialize SQLite + AppSession, start idle lock, route Welcome or Unlock.

Assembly: CipherBank-app · Shell · Kind: on-device C# · Wire: never sends mnemonic/PIN/spend keys

Logic: GoTo Splash → parallel BootSessionAsync(db.Initialize + session.Boot) with MinSplashDuration → idleLock.Start → GoTo Unlock|Welcome.
